# Календаризация команд

Интерактивный дашборд загрузки команд, ролей и пересечений по неделям.

Сейчас в каталоге актуальный таймлайн **3–4Q 2026**: Монетизация, Домашний интернет, ДГП, МегаИнтернет и Тарифы. Роуминг/VAS в текущий состав не входит. Новые таймлайны подключаются без изменения логики: достаточно файла данных и записи в `timelines.json`.

## GitHub Pages

Сайт публикуется из ветки `main`, папка `/`.

**Settings → Pages → Build and deployment → Source: Deploy from branch → main → / (root)**

URL: `https://<username>.github.io/q3-calendarization-2026/`

## Локальный запуск

```bash
python3 -m http.server 8080
```

Откройте http://localhost:8080

Без сервера можно открыть `index-standalone.html`.

Проверка логики обработки:

```bash
node --test test/*.mjs
```

## Файлы

- `index.html` / `styles.css` / `app.js` — интерфейс
- `process.js` — расчёт пересечений и недельной сводки
- `timelines.json` — каталог таймлайнов
- `roster.json` — штат по ролям и командам (ёмкость человеко-дней)
- `data-h2-2026.json` — актуальная календаризация 3–4Q 2026
- `data.json` — исторический снимок 3Q 2026 (июль), для регрессии пересечений, в каталог не входит
- `index-standalone.html` — всё в одном файле
- `scripts/build_calendar.py` — сборка `data-h2-2026.json` из файлов в `incoming/`
- `test/process.test.mjs` — сверка расчётов с эталоном 3Q 2026

## Как добавить новый таймлайн

1. Положите JSON рядом с `data.json`, например `q4-2026.json`.
2. Добавьте запись в `timelines.json`:

```json
{
  "id": "q4-2026",
  "title": "4Q 2026",
  "period": "5 октября — 28 декабря 2026",
  "file": "q4-2026.json"
}
```

3. Пересоберите standalone при необходимости: `python3 scripts/build-standalone.py`

Чтобы пересобрать актуальную календаризацию из исходников в `incoming/`:

```bash
python3 scripts/build_calendar.py
python3 scripts/build-standalone.py
```

Нужны `openpyxl` (Excel) и `jpype1` + `mpxj` (MS Project `.mpp` команды Тарифы).

Минимальный формат файла данных:

```json
{
  "generated": "2026-08-15T12:00:00",
  "teams": {
    "МегаИнтернет": { "full": "МегаИнтернет", "color": "#548235", "bg": "#E2EFDA" }
  },
  "weeks": [{ "iso": "2026-10-05", "label": "05.10" }],
  "entries": [
    {
      "team": "МегаИнтернет",
      "task": "Название задачи",
      "resource": "Имя",
      "role": "FE",
      "ticket": "B2CPROD-1",
      "type": "деливери",
      "weeks": { "2026-10-05": "5" }
    }
  ]
}
```

`conflicts` и `weekly` можно не присылать — сайт считает их сам по той же логике, что и для 3Q 2026:

- пересечение = одна роль занята у двух и более команд на одной неделе;
- в клетке недели — число дней занятости (как в таймплане МегаИнтернета: `5`, `2`, `отпуск`);
- человеко-дни по специальности: спрос из клеток ганта, ёмкость из `roster.json` × **22 рабочих дня на человека в месяц**;
- Фикса = Домашний интернет (ДИ), Репрайсы = Монетизация; совмещённые люди считаются один раз;
- Монетизация без дизайнера и роли без штата (например Контент) дают дефицит на весь спрос;
- отпуск учитывается в загрузке; в список задач пересечения не попадает, если у той же команды и роли на этой неделе есть обычная занятость;
- подпись задачи в пересечении обрезается до 45 символов.

Если в файле нет `teams` или `weeks`, они восстанавливаются из `entries`.
